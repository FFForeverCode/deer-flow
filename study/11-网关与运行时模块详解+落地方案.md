# 11｜网关与运行时模块详解 + 落地方案

> 覆盖模块：Gateway Router / Service、RunManager、Worker、StreamBridge、Run Store。

---

## 1. 模块边界

### 1.1 Gateway Router（协议层）

- 目录：`backend/app/gateway/routers/`
- 关键文件：`backend/app/gateway/routers/thread_runs.py`、`backend/app/gateway/routers/runs.py`
- 责任：接 HTTP、做参数校验/权限注解、调用 service。

### 1.2 Gateway Service（生命周期层）

- 文件：`backend/app/gateway/services.py`
- 责任：统一 run 创建、配置合并、线程归属校验、启动后台执行、SSE 消费、wait 语义。

### 1.3 Runtime（执行层）

- 文件：`backend/packages/harness/deerflow/runtime/runs/worker.py`
- 责任：执行图、发布事件、处理 run 终态与清理。

### 1.4 运行状态与事件（管理层）

- 文件：`backend/packages/harness/deerflow/runtime/runs/manager.py`
- 相关：`backend/packages/harness/deerflow/runtime/stream_bridge/base.py`
- 责任：run 状态机、取消策略、跨组件事件桥接。

---

## 2. 真实执行链路（代码级）

1. `thread_runs.py` 接收 `POST /{thread_id}/runs/*`；
2. 路由调用 `services.py:start_run(...)`；
3. `start_run` 解析输入、构造 config/context，`resolve_agent_factory(...)`；
4. `asyncio.create_task(run_agent(...))` 启动后台执行；
5. `worker.py:run_agent(...)` 执行 agent graph 并发事件；
6. `sse_consumer(...)` 订阅 bridge 并推送 SSE；
7. `wait_for_run_completion(...)` 提供非流式同步等待语义。

---

## 3. 关键实现点（你必须看懂）

### 3.1 `start_run` 的 6 个关键动作

1. **鉴权与线程归属校验**（避免跨用户 run）；
2. **输入规范化**（消息格式、上下文字段清洗）；
3. **模型 allowlist 校验**（拒绝未配置模型）；
4. **agent factory 解析**（默认 lead agent）；
5. **run config 合并**（context/configurable/internal 字段治理）；
6. **后台任务启动**（run 与请求生命周期解耦）。

### 3.2 `run_agent` 的 4 大职责

1. 构造 runtime context（thread_id/run_id/app_config）；
2. 执行 graph 的流式迭代；
3. 把 chunk 写入 StreamBridge（供 SSE/调试消费）；
4. 最终状态收敛（success/error/timeout/interrupted）。

### 3.3 StreamBridge 的设计价值

- 让“执行”和“传输”松耦合；
- 支持心跳/终止哨兵；
- 支持断线重连消费。

---

## 4. 为什么这么设计

1. **长任务不能绑死 HTTP 请求线程**；
2. **run 必须是一等实体**（可取消、可追踪、可审计）；
3. **兼容 stream 与 wait 两类客户端**；
4. **容错语义统一在 service/runtime，而不是散在路由层**。

---

## 5. 完整落地方案（从 0 到可用）

### 5.1 数据模型

定义 `RunRecord`（至少包含）：

- `run_id`
- `thread_id`
- `status`（pending/running/success/error/...）
- `created_at`/`updated_at`
- `error`
- `task_handle`

### 5.2 接口设计

至少提供 5 个接口：

1. `POST /threads/{id}/runs`
2. `POST /threads/{id}/runs/stream`
3. `POST /threads/{id}/runs/wait`
4. `POST /threads/{id}/runs/{run_id}/cancel`
5. `GET /threads/{id}/runs/{run_id}`

### 5.3 服务层

实现 `start_run`：

1. 构造 run record 并入 run manager；
2. 构造 graph input + runtime config；
3. 后台执行 `run_agent` 并把 task 回填到 record。

### 5.4 执行层

实现 `run_agent`：

1. 创建 agent graph；
2. 执行并监听 chunk；
3. chunk 写入 bridge；
4. 收敛终态并发 END 事件。

### 5.5 流式层

实现 `sse_consumer`：

1. 订阅 bridge；
2. 识别 heartbeat/end sentinel；
3. 客户端断开时按策略 cancel/continue。

---

## 6. 工程风险与规避

1. **重复提交同线程并发 run**：要有 multitask_strategy；
2. **客户端断线导致半状态误判**：wait 模式要检测 END_SENTINEL；
3. **store 与内存状态漂移**：run state 要统一来源与回写点；
4. **取消 race condition**：cancel path 要区分本地持有/远端持有 run。

---

## 7. 验收清单

- 能流式收到中间事件与结束事件；
- run 可查询且状态迁移正确；
- cancel 可中断执行且终态一致；
- wait 不会把半成品 checkpoint 当最终结果返回；
- 断线重连不会导致 UI 假死或 run 泄漏。
